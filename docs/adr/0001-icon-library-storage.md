# 存储结构按“图标库”预留,而非单图标

## Status
accepted

## Context

本轮只做“上传一张自定义图标并替换 favicon”,但产品的方向已经明确:将来会支持**多图标点击切换、动态图标、图标库**,并且“恢复默认”只清当前生效标记、不删图标文件(为将来手动删除历史图标留空间)。如果现在按“单图标、固定文件名 + meta.json”存,将来做图标库时就得迁移磁盘结构。

## Decision

图标存储从一开始就按图标库形态 `$DSH_HOME/custom-favicon/` 设计:

- 每个图标一个独立文件(如 `library/<id>.<ext>`),而不是固定 `icon.<ext>`;
- 一份索引/元数据记录每个图标及其状态;
- 一个“当前生效图标”标记,指向当前正在使用的那个 id;
- “恢复默认”只清除该标记,不删任何图标文件;
- 本轮只写入并使用其中一个槽位,但目录结构与读取路径按“可能有多个”实现。

存储位置用 `$DSH_HOME`(环境变量,缺省 `~/.dsh`),不绑定本地绝对路径,使插件在任意机器/用户上通用(发布给他人安装的前提)。

## Consequences

- 现在实现的读取/写入代码要多一层“遍历索引/按 id 取文件”,比单图标略复杂。
- 将来做多图标/切换时,不需要迁移磁盘格式,只需在上层加交互。
- 旧的单图标写法(固定 `icon.<ext>`)被放弃;任何已经按旧格式落盘的图标不会被读取(本轮尚未发布,无迁移负担)。
