# 谁在被看着:由页面说的三件事决定,不再靠保留计数

## Status

accepted(修订 0.11.x 起用 `retainedBy.mainView` 当"正在看"的那条实现决定)

## Context

停留计时器要回答一个前置问题:「**用户此刻在看哪个会话?**」0.11.x 的答案是 DSH 的**保留计数**——`retainedBy.mainView > 0`,即"这个会话最近被打开过、还没被释放"。每个被保留的会话各上一根计时器(当时是为了修"点进去也不消":只认一个 id 时,切换期间真正在看的那个常轮不到)。

这个信号的问题在 0.12.0 之后被放大了。它的语义是"最近打开过、还没释放",**不是"屏幕上显示着"**:切到「插件 / 设置 / 模型」这类全局面板时,对话面板被替换,而那个会话的保留不一定马上归零。于是计时器照跑,2 秒后把它的旧结束标成已读。以前这只影响一台浏览器,现在已读存在宿主,一次误判**等于替所有设备清掉红点**——用户看到的现象是"我没点开过的会话,红点自己没了"。

同时,DSH 自己早就有正确判据:`panelInfo.activePanelId`——ui-workspace 的侧栏就是用它决定"当前会话"要不要高亮(`usePanelInfo((info) => info.activePanelId !== null)`,非 null 表示全局面板盖住了对话)。

## Decision

**"谁在被看着"改由页面自己说的三件事决定,按优先级取第一个能用的:**

1. `panelInfo.activePanelId !== null` → 全局面板盖住了对话 → **谁都不算**(和 DSH 自己的侧栏同一条判据,走标准 prop `usePanelInfo`,不读 DOM);
2. `document.visibilityState === 'hidden'` → 标签页不在前台 → **谁都不算**(`visibilitychange` 触发重算);
3. DOM 上的 `[data-conversation-session]` 说出了屏幕上正渲染的那个会话 → **只算它**(残留的另一个保留不再牵连);
4. 三个信号都拿不到(旧构建、探针失败) → **退回保留计数**,即 0.12.0 之前的行为。

水位线、停留计时的语义(ADR 0006:进入上弦、快照固定、不追认停留期间的新结束)全部不变;改的只是"哪几个会话算正在看"。

## Consequences

- **修掉了"没看却被标已读"**:切到「插件 / 设置」页、标签页切到后台、以及残留保留,都不再清任何红点。
- **失效姿态是"退回旧行为",不是"红点不消"**:三个信号任一取不到,行为与 0.12.0 相同(可能误判);不会出现"点进去也不消"那种更糟的失败。
- **切到后台再回来会重新上弦**(等价于离开 + 重新进入):回来待够 N 秒仍会标已读,这符合 ADR 0006 的"离开即拆表"。
- **窗口被别的窗口挡住,浏览器不告诉页面**,所以仍算"在看"。要挡住它只能靠 `document.hasFocus()`,而多显示器下"浏览器没焦点但人在看"会被误伤,未采用。
- 测试锁在 `test/unread-clear.mjs` 的「屏幕报表」一节:全局面板 → 空集;后台标签页 → 空集;DOM 指名 → 只算它;三个信号都没有 → 退回保留计数;两个探针各自的正反例。

## 备选方案(未采用)

- **只读 DOM**——属性随时可能被 DSH 改名,而 `panelInfo` 是官方 API、和侧栏同源,所以以官方信号为主、DOM 只用来"精确到哪一个"。
- **要求 `document.hasFocus()`**——多显示器误伤(浏览器没焦点但人在看),代价大于收益。
- **继续只用保留计数**——就是被修掉的那个 bug。
