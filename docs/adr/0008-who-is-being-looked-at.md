# 谁在被看着:由页面说的三件事决定,不再靠保留计数

## Status

accepted(修订 0.11.x 起用 `retainedBy.mainView` 当"正在看"的那条实现决定)

## Context

停留计时器要回答一个前置问题:「**用户此刻在看哪个会话?**」0.11.x 的答案是 DSH 的**保留计数**——`retainedBy.mainView > 0`,即"这个会话最近被打开过、还没被释放"。每个被保留的会话各上一根计时器(当时是为了修"点进去也不消":只认一个 id 时,切换期间真正在看的那个常轮不到)。

这个信号的问题在 0.12.0 之后被放大了。它的语义是"最近打开过、还没释放",**不是"屏幕上显示着"**:切到「插件 / 设置 / 模型」这类全局面板时,对话面板被替换,而那个会话的保留不一定马上归零。于是计时器照跑,2 秒后把它的旧结束标成已读。以前这只影响一台浏览器,现在已读存在宿主,一次误判**等于替所有设备清掉红点**——用户看到的现象是"我没点开过的会话,红点自己没了"。

同时,DSH 自己早就有正确判据:`panelInfo.activePanelId`——ui-workspace 的侧栏就是用它决定"当前会话"要不要高亮(`usePanelInfo((info) => info.activePanelId !== null)`,非 null 表示全局面板盖住了对话)。

## Decision

把一直混在一起的两个问题拆开:

### A.「这个页面在哪个会话上」——决定"进入/离开",也就是快照什么时候丢

按优先级取第一个能用的:

1. DOM 上的 `[data-conversation-session]`:屏幕上正渲染的那个会话 → 就是它(残留的另一个保留不再牵连);
2. `list.current`(运行时给出的当前会话);
3. 退回保留计数(`retainedBy.mainView > 0`),即 0.12.0 之前的行为。

**只有这个集合变化才算"离开"**:会话 A 离开集合 → 它的"进入时快照"被丢弃 → 下次再进来重新取快照(这正是"看过"被确认的方式,ADR 0006)。

### B.「此刻在不在看」——只决定计时器跑不跑(暂停)

- 标签页在前台:`document.visibilityState !== 'hidden'`;
- 对话没有被全局面板盖住:`panelInfo.activePanelId === null`(标准 prop `usePanelInfo`,和 DSH 自己的侧栏同一条判据)。

暂停期间**不确认任何东西**,但 A 仍然在集合里、快照也留着;恢复之后接着用**旧快照**数满 N 秒。

> 0.15.0 把 B 的两个信号当成了 A(直接返回空集),于是"切标签页"被当成了"离开":空集 → 快照被删 → 回来重新取快照 → 2 秒后把你在场时结束的那一轮标成已读,也就是**红点自己消失**。0.15.2 起两者分开。

水位线与停留计时的语义(ADR 0006:进入上弦、快照固定、不追认停留期间的新结束)一律不变;改的只是"哪几个会话算正在看、什么时候算离开"。

## Consequences

- **修掉了"没看却被标已读"**:全局面板盖住对话、标签页在后台时,计时器停着,不会确认任何东西——残留保留也不再牵连(DOM 直接指名屏幕上那一个)。
- **暂停不再等于离开**:切标签页、切到「插件 / 设置」页都只是暂停,回来接着用旧快照;你在会话里看着它跑完的那一轮**仍然亮着**,直到你**去别的会话再回来**(这才是 ADR 0006 说的"切走再进来")。
- **失效姿态是"退回旧行为",不是"红点不消"**:A 的三个信号都取不到 → 退回保留计数;B 的信号取不到 → 按"在看"处理(即 0.12.0 的行为,可能误判)。两种情况都不会出现"点进去也不消"那种更糟的失败。
- **窗口被别的窗口挡住,浏览器不告诉页面**,所以仍算"在看"。要挡住它只能靠 `document.hasFocus()`,而多显示器下"浏览器没焦点但人在看"会被误伤,未采用。
- 测试锁在 `test/unread-clear.mjs`:「暂停 ≠ 离开」一节跑完整时间线(后台/面板暂停不计时、切标签页回来红点仍亮、去别的会话回来才确认);「屏幕报表」一节锁住两个暂停信号**不改变**会话集合,以及 DOM 指名/退回保留计数。

## 备选方案(未采用)

- **暂停也算离开**(0.15.0 的实现)——快照被删、回来重新取,等于"离开又进来",用户实测"切一下标签页红点就没了"。
- **只读 DOM**——属性随时可能被 DSH 改名,而 `panelInfo` 是官方 API、和侧栏同源,所以面板/后台用官方信号、DOM 只用来"精确到哪一个会话"。
- **要求 `document.hasFocus()`**——多显示器误伤(浏览器没焦点但人在看),代价大于收益。
- **继续只用保留计数**——就是最初被修掉的那个 bug。
