# 黄点是「进行中」的第二次投影,不覆写官方那一行

## Status

accepted

## Context

需求是"一眼看出哪个会话在跑、有几个在跑,而且在工作区数字、会话行、左上角、标签页这四处都看得见"。动手前查实的三条官方事实决定了这个功能的形状:

1. **官方早在会话行上做了「进行中」。** 每会话的 `running` 一旦为真,ui-workspace 就在行首那 16px 格里渲染 `StateDot` 的 `ongoing`——一颗**灰色**转圈环(1.5s、`--dsw-alias-label-tertiary`,官方注释原话是 "a quiet full ring",刻意做得安静);一旦停下来等你审批 / 回答 / 计划待审,它换成**琥珀色**实心点(官方 warn 色 `#f59e0b`),并把行上的时间换成「等待审批 / 等待回答 / 计划待审」短标签。也就是说,我们要做的不是补一个缺失的指示,而是**把同一个状态换成看得见的黄**。
2. **官方的行首席位在"在跑"时根本不可用。** `sidebar.session.row.leading` 只在行的主状态为 idle 时才被渲染(`showStatus ? <SessionStatusDots/> : renderSlot(...)`),所以"在跑"的时候轮到的是官方那颗点,不是我们的席位;要往那一格放东西,只能覆写官方渲染。
3. **`running` 是官方宿主算好的进程内事实。** 宿主侧就是 `ctx.agents.get(id)?.status === 'running'`,经 `api-session/status` 事件实时推到浏览器,客户端会话列表里本来就带着它;冷会话一律 `running:false`,进程重启不留残留,页面刷新时列表首帧就是对的。子代理会话不进侧栏(官方 `sessionVisible` 直接对 `origin === "subagent"` 返回 false),在跑的会话行也不会被官方"折叠 5 条"收起(`collapsedSessionRows` 对 `running` 放行)。

本仓库已有的两条纪律也压在这里:ADR 0004「只认官方、不遮蔽官方渲染树、不接第三方」,以及 ADR 0008「屏幕事实只读官方信号」。

## Decision

**把官方的 `running` 原样读进来,在四个位置重新投影成黄色;一处官方的东西都不动。**

- **口径与官方那颗灰转圈完全等价**:`running && 没有待交互 && 不是子代理会话`。第三种"等待交互优先"不是我们另定的例外——官方那一行就是这么排的,所以黄点与灰转圈同进同出,等你时两者都不亮。
- **事实只读,不落盘**:客户端从已有会话列表的 `running` 推导(`useSessionStatus` 优先、列表行 `running` 回退,与官方 `sessionNode` 同序)。不新增投影、不新增宿主接口、不持久化"进行中"。
- **四处投影**:侧栏「工作区」标题后面是**黄数字**(此刻有几个在跑;红数字仍在右上,黄的在右下)、工作区文件夹图标上是**黄点**、会话行上是**黄点**(两处都是**左红右黄**)、左上角品牌位与标签页图标**右下角是同一个数字**(红数字仍占右上角)。
- **两个数字与未读数上下排,两个点与未读点左右排**:数字占角(右上红 / 右下黄),点在行内成对(左红右黄)。文件夹图标上的红点在黄点出现时向左让出一个点的宽度,黄点消失后立刻退回原处——未读标记单独在场时,位置和以前一模一样。
- **不碰官方**:不占 `sidebar.session.row.leading`(结构上用不了),不覆写官方 CSS 类名(不把灰转圈染黄,也不隐藏它),只往官方行里插自己的元素——沿用现有 `data-icon-custom-*` 注入管线、reconcile 重绘、失败熔断。
- **开关是偏好,不是事实**:宿主只存一个布尔(`running.json`,独立一对 `getRunningRule` / `setRunningRule`),与红点规则各存各的、互不牵连;黄点开关关掉,红点一个都不少,反之亦然。落盘的永远是"要不要显示",不是"谁在跑"。

## Consequences

- **同一行会同时有三颗点**:官方灰转圈(它自己也在说在跑)、我们的黄点(在跑)、我们的红点(有未读)。重复是刻意付出的代价:用户明确要求"不要管官方,只在原本有红点的地方加个黄点",换来的是一行都不依赖官方类名与结构,官方改版最多让黄点变成"不显示"。
- **两颗数字必须等大**。它们有时同处一个很小的画布(标签页 16px、logo 24px),第一版让黄的那颗去"占红的那颗剩下的地方",结果就是一大一小 —— 用户一眼就看出来了。现在反过来:**两颗同时在场时一起缩到画布容得下的同一个尺寸**(标签页按"四个半高 + 两个白圈 + 一道缝"算,logo 按"各占一半减一道缝"算),只有一颗时才保持设置里那个大小。这样牺牲的是一点点字号(16px 上本来就读不太清),换来的是"这不是渲染坏了"。
  由此还有一条明确的取舍:**两颗同时在场时,设置里的"红点大小"三档画出来完全一样** —— 画布/logo 就那么大,再分三档只会让"小"档在 16px 上彻底读不出来,而且同一组数字会因为换档突然变大变小。所以档位只管"单独出现"的那一刻(也即平时最常看到的那颗红数字),设置页的大小选择器下面直接把这句话写给用户看。
- **0.18.0 的第一版在工作区那一行栽过一次**:黄数字当时被插在"名字持有者之后",而那个持有者就是工作区那一行本身,它的父元素是纵向容器——于是黄数字成了一个被 `align-items: stretch` 拉满的 flex 子项,画成一整条通栏。结论写进测试:工作区的黄标记必须是与红点同级的**绝对定位点**,谁都不许再往名字旁边插流式节点(`test/running-mark.mjs`)。
- **黄点不依赖红点那套宿主投影**:`sessionProjections` 缺失时,红数字会丢,黄点照常工作——两者的事实来源本来就不同。
- **刷新即正确,崩了也不留假亮**:可见性完全跟随官方 `running` 的推送,没有本地时间戳、没有水位线、没有需要清理的残留。
- **行内黄点只在行真的渲染时存在**:工作区整体折叠时看不到行内黄点,但工作区那一行的黄数字仍然说着"这个工作区里有几个在跑"。
- **黄色的色值是有讲究的**:官方没有黄色 token,而官方"等你"的琥珀 `#f59e0b` 会出现在同一列的不同行上,所以这里用一个字面量金黄 `#f5c518`(和现有红 `#e5484d` 一样是字面量),避免"等你的会话"和"在跑的会话"读混。
- 数字上限沿用角标那套 `99+`,不另立规矩。

## 备选方案(未采用)

- **把官方那颗灰转圈染色成黄**(`[data-row-key^="session:"] .spinner { color: ... }`):零新增元素、位置天生正确、也不重复。放弃的理由是它要覆写官方渲染树的样式——官方改类名就静默失效,而失效的样子是"什么都没发生",这正是最难查的一类故障;而且它把"不碰官方"这条已经写在 README 与 ADR 0004 里的承诺撕开一个口子。
- **只让官方灰转圈说话,插件不做行内标记**:最省、最不重复,但你要的是"一眼可见的黄",而官方那颗点是灰的、安静的,且只在行首 16px 格里。
- **占用 `conversation.session.header.corner`(真·右上角)或行首席位**:前者是 `single` 席位,占位等于把官方那个控件拆掉重写;后者在"在跑"时根本不挂载。两者都与 ADR 0004 相反。
- **自己落盘一份"进行中"记录**:多一份可能过期的真相,无法比官方进程内事实更准,而且崩溃 / 重启后的假亮点需要额外的超时与清理逻辑才能消掉。
- **只做聚合(工作区数字 + 左上角 + 标签页),行内交给官方**:这是"不重复"的干净解,但用户明确要行内黄点——行内是"从数字下钻到具体会话"的那一步。
