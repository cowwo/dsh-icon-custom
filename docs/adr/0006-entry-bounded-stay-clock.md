# 停留计时器由「进入会话」上弦,不追认停留期间的新结束

## Status

accepted(修订 ADR 0004 里"停留计时"那一条)

## Context

0.10.0 引入「进入会话后连续待满 N 秒才算已读」时,计时器的**上弦时机**是"又结束了一轮":`staySignature` 里带着 `lastTurnEnd.endAt`,新结束一到就重新上弦;到点后的 `attempt()` 读的是**当下最新**的 `endAt`,并且每 2 秒看门狗式重试一次(注释原话:"防止新结束和计时器赛跑把红点永久留下")。

于是出现了一个没人能看见的红点:

- 用户在会话里发消息 → 回合结束(实测数据:第 2 回合 `completed` 于 `05:30:57.567`);
- 计时器上弦,5 秒后(`05:31:02`)把**刚结束的这一次**标成已读;
- 用户读完回答再看红点——早就没了。

把真实时间线喂进真实代码回放,三种情形一起说明了问题:

| 情形 | 红点 |
|---|---|
| 你一直待在这个会话里(延迟 5 秒) | 亮 5 秒 → 灭 |
| 你切走再切回来 | 切回来后再数 5 秒 → 灭(**"回来才消"也做不到**) |
| 延迟设成 0 | 逻辑上从不出现(同一帧里就被标记) |

同时,README 里一直写着两条互斥的规则:第 61 行「要清掉它,**切走再切回来**即可」(进入才消),和延迟项「**连续待满 N 秒**才算看过」(停留就消)。代码执行的是后者,用户的直觉是前者。

第三条事实:0.9.2 特意取消了「正在看的会话不算未读」这条例外,目的就是让"我正看着的会话跑完了"这件事**亮起来**;而"停留满 N 秒就自动标掉最新的结束"实际上把这条例外从后门装了回来。

## Decision

**计时器由"进入会话"上弦,且上弦那一刻的快照是固定的。**

- 被看着的会话集合发生变化(进入/离开)时,才上弦;集合没变时,新结束**不重跑计时器**(依赖项只有"被看着的会话集合"和延迟秒数)。
- 上弦时按会话记下 `id → endAt` 的快照,**停留期间不刷新**。到点只标记**快照里那个 `endAt`**,不去读"当下最新"的值。
- 因此:进入时已经存在的结束 → 待满 N 秒消;你人已经在里面时新结束的那一轮 → **不上弦、也不追认**,一直亮到**你切走再进来**(那时会取一份新快照)。
- 到点是**单次**的:快照固定,没有可追的东西,原来的 2 秒看门狗删除(它追的正是这条规则不要的那次结束)。
- 会话离开视野即丢掉快照,所以"再进来"天然等于重新上弦;`clearDelaySec = 0` 的语义不变(进入即已读),只是停留期间的新结束同样要等下次进入。

顺带删掉了只为旧签名服务的 `stayKeyFor()`:签名现在是"被看着的会话 id 集合",不再掺 `endAt`。

## Consequences

- **修好了用户报告的故障**:你在会话里看着它跑完,红点会**一直亮着**,直到你切走再进来。回归测试用 `session-3b40e835` 的真实时间戳锁住了这一条(`test/unread-clear.mjs`)。
- **README 的两条规则重新合成一条**:第 61 行的「切走再切回来即可」现在与延迟项一致,延迟项补上了"只认进入时已存在的那次结束"。
- `clearDelaySec` 的含义收窄了一点:N 秒保护的是"你**进入**时看到的那次结束",不再保护"停留期间到达的结束"——后者不需要保护,它本来就该一直亮着。
- 代价:如果一个会话在你眼皮底下反复结束(连续对话),它的红点会一直亮着,直到你切走再回来。这是规则的本意(那正是你要它提醒的事),不是漏清。
- 时钟域的老坑没有回来:新实现里**没有任何跨钟比较**——只比较"快照里的 `endAt`"与"宿主域水位"(两者同域),不掺浏览器的 `Date.now()`。
- 每个被看着的会话各有一份快照;面板"一键全部标记已读"仍然直接写水位,与计时器互不干扰。

## 备选方案(未采用)

**规则 B(停留满 N 秒即把最新结束标为已读)**:即原实现。优点是"你就坐在那儿,所以你看过了"这种直觉上的省事;缺点是你在场时结束的那一轮会把红点闪一下就没,等于 0.9.2 的例外又回来了,而且"切走再切回来"变成空操作(回来照样 5 秒消)。
