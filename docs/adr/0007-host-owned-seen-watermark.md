# 「已读」水位线搬到宿主:一份 JSON、逐会话取 max

## Status

accepted(修订 ADR 0004 里"水位线存在浏览器"那一条)

## Context

0.10.x 把「我看过这个会话」记在浏览器自己的 localStorage(`dsh-icon-custom.unread-seen.v2`)。当时的理由写在那段代码的注释里:*"have I already looked at this session" is a fact about this browser*。这个理由有一半是对的,但它带来的三个后果越来越明显:

- **同一件事在不同设备上不是一个答案。** 设备 A 上点进去看过的那几条,设备 B 不知道。用户在 A 上看到 1 个红点、在 B 上看到 5 个,而这**不是数字算错**,是水位线各存各的;
- **B 的初值来自 B 自己上次在线的时间。** `ensureSeenBaseline` 给"这台浏览器第一次见到"的会话打的基线是 `seenBootAt`(本浏览器上次开着页面的时刻)。所以设备 B 关着的那段时间里结束的每一轮,在 B 看来全算未读——B 放得越久,回来时红点越多;
- **清掉浏览器数据 = 全部未读。** 换 profile、无痕窗口、清站点数据,都会把水位线一起清掉;出问题时也只能靠 devtools 读 localStorage 排查。

同时,红点本身的语义已经被 ADR 0006 固定为「有一条结束我还没看」,判定精度不变(进入会话 + 连续待够 N 秒)。所以这一版改的**只是水位线存在哪里**,不是它怎么算。

## Decision

**水位线的真相搬到宿主:`$DSH_HOME/custom-favicon/unread-seen.json`;每个浏览器保留一份缓存兼离线队列。**

- 文件形状 `{ "version": 1, "seen": { "<sessionId>": <endAt> } }`。空文件、版本不认识、内容坏掉 —— 一律当**空表**,绝不猜着读(猜错会把红点全点亮)。
- **合并逐会话取 max,标记永不倒退。** 这是这套东西唯一的并发保护:两个浏览器(或两个 dsh 进程)同时写,后写者也不会把别人更新的标记盖回旧的——那会让已清掉的红点"诈尸"。整个表一起发,幂等,重复发无害。
- **浏览器那份不删,降级为缓存 + 离线队列。** 红点永远读本地那份,所以页面不等往返、断网照常工作;每次打开页面把并集推回宿主一次,这同时就是**迁移**(0.11.2 之前的本地标记)和**自愈**(宿主文件丢了/被剪枝了,这份补回去)。
- **读走现有端点。** `getUnreadRule` 的响应里多一个 `seen` 字段(老客户端忽略未知字段即可,和 `hostNow` 同一个套路),写新增 `setUnreadSeen` 一个端点。
- 写盘是 **temp + rename**;失败只告警不抛(和 `unread.json` 一样是 advisory 文件)。
- 每库最多 400 条,按 `endAt` 保留最新。**剪枝不会把红点变回来**:客户端对没有标记的会话按"这台浏览器上次在线"重新起基线,老结束仍算已读。
- 水位线的**时钟域不变**,仍是宿主域(`turn/end.time` 也是宿主域),`hostNow` 与 v1→v2 折叠逻辑都保留。

配套的两条,属于精度而不是存储:

- **会话行的红点只画在属于它的行上。** 定位只认 DSH 自己的 `data-row-key`;目标会话的行没渲染(折叠、工作区收起)就**不画**,不再退化成"全侧栏按标题找"——那个退化正是"三个同名会话挤出一行三个红点"的原因。折叠会话由**工作区行点**与**待处理清单**代表。
- **工作区行也按 `workspace:<id>` 定位**(显示名 ≠ 存储标题、两个工作区同名,都不再让文件夹点消失)。

## Consequences

- **红点跨设备一致了。** 任何一台设备上"看过了",所有设备都不再提醒;`unread-seen.json` 可以直接读、可以直接删(删掉 = 退回"按每台设备的上次在线时间重新起基线")。
- **另一台设备不用刷新也会收敛。** 页面可见时每分钟(以及每次切回前台)向宿主采一次水位线,采纳后立即重绘——最迟约一分钟,刷新则立刻。宿主不主动推送,所以这是"够用且不引入新通道"的折中。
- **清浏览器数据不再等于全部未读。** 宿主那份还在,页面一打开并集就回来了。
- **代价(明确接受)**:水位线不再区分设备——手机上看过,台式机也不再提醒。这是"跨设备一致"的另一面,不是漏做。判定精度仍由 `clearDelaySec` 与 ADR 0006 那条"进入才算"的规则控制(把 N 调大,一眼扫过就不算看过)。
- **老宿主 + 新客户端 = 安全降级**:`setUnreadSeen` 打不通时标记留在本地、按 30 秒起步的退避重试(上限 5 分钟),红点照常工作;宿主的 `seen` 缺失时客户端只是不合并。反过来(新宿主 + 老客户端)也一样:老客户端忽略 `seen` 字段,继续只用自己的 localStorage。
- **测试**:`test/unread-seen.mjs` 锁宿主的纯逻辑(脏输入、max 合并、剪枝、文件形状),`test/unread-host-sync.mjs` 锁客户端的同步行为(并集推送、心跳不推、失败重试与退避、收敛)。宿主那三个真方法(载入/落盘/合并)另用一次性脚本对真实文件系统验过:重启后仍在、未来版本当空库、坏文件不炸、无 `.tmp` 残留、目录不存在时自动建。
- **typert 清单**:新增一个 invocation(`setUnreadSeen`),`getUnreadRule` / `setUnreadRule` 的结果 schema 多一个 `seen` 字段;发布前两道闸(peer 范围 + typert 清单)都跑过,8 个 invocation 全通过。

## 备选方案(未采用)

- **全局水位线放宿主(不分设备)** —— 就是本方案;早前的备选是"按设备各存一份"(`设备id → { 会话id → seenAt }`),行为更精细但要先解决设备身份从哪来(前端自生成 UUID 会随清数据换身份,宿主连接 peer 又是连接级、刷新就变),复杂度不划算。
- **水位线塞进会话日志**(作为会话事件)—— 污染会话事实,而且"已读"是 UI 私事,不该进日志。
- **用官方 `dsh-storage-json`** —— 带 unit/version 与启动校验,对"丢了也能活"的水位线属于过度设计;放在插件自己的目录里与 `unread.json` 并排更合适。
