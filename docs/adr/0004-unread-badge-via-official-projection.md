# 未读红点:用官方 session projection 折叠 `turn/end`,规则由用户勾选

## Status

accepted(其中「停留计时」一条由 [ADR 0006](./0006-entry-bounded-stay-clock.md) 修订:计时改由「进入会话」上弦,不追认停留期间的新结束)

## Context

需求是「图标右上角显示"有几件事在等我"」。讨论后定为**信箱**语义(会累积、要清),而不是官方的**门铃**(只描述此刻"谁卡在等你")。

查完官方能力后,三条事实决定了做法:

1. **官方没有任何"通知/未读"接口**。唯一天生就是计数的只有客户端标准 prop `useSessionPendingInteraction`(覆盖"审批/提问/计划待审",是门铃不是信箱)。
2. **官方有一个统一的发布通道** `ctx.sessionProjections`:注册一个 key + 一个**纯 fold**,框架负责订阅会话事件、每会话缓存、变更通知,并把值随会话列表送到浏览器(`SessionListEntry.projectionValues`)。官方文档对它的描述就是"两侧互不认识"(capability seam)。
3. **官方客户端有个 `completed` 字段**("结束了、你没打开过"),语义正好,但它是**客户端内存态**:`prevRunning` 从空开始,刷新页面后已经 idle 的会话不再产生提醒。对 favicon 红点(会频繁刷新)不可靠,不能依赖。

另外官方 `turn/end` 有 6 种 `reason.kind`(`completed` / `aborted` / `blocked` / `error` / `max-tokens` / `interrupted`),`aborted` 还带一层取消来源——"你自己按的停止"和"重启导致的中断"必须能分开。

## Decision

### 事实与规则分离

- 投影只存**事实**:`lastTurnEnd = { endAt, reason }`,即「这个会话最后一次是怎么结束的、什么时候」。
- 「哪种原因值得亮红点」是**用户设置**,在客户端套用。好处:勾选/取消**即时生效**,不需要回头重折任何会话日志,也不需要为每种组合各存一份状态。

### 只认官方

- 输入只有官方:`session/event`(经投影框架)、客户端标准 prop `useSessions` 与 `useSessionPendingInteraction`。
- **不接任何第三方通知插件,也不预留第三方插口**。第三方关心的"干完/报错/卡住"本来就是官方事实,因此不接它也已经覆盖。
- 投影用 **`ctx.inject(['sessionProjections'], …)` 可选注册**:部署里没有这个框架时,只丢红点数字,**不影响图标本体**。这个插件首先是显示插件。

### 规则:7 种原因 + 门铃,逐项可勾选

`completed`、`error`、`blocked`、`max-tokens`、`interrupted`、`aborted:user`、`aborted:other`,外加"有人在等我"。默认**除了 `aborted:user` 全部打开**(你自己按的停止不必提醒你)。

未知原因(将来 DSH 新增一种)默认**不亮**——词汇表增长不会带来惊喜。

### 已读 = 打开过

- 用**每个浏览器**一份的 localStorage 水位线 `seen[sessionId]`。这是关于"这个浏览器看过没有"的事实,不属于宿主。
- 首次见到某个会话时,水位线取**上次这个浏览器还开着的时间**。于是:关着页面时发生的结束**仍然算未读**(你回来能看见),而**装插件之前的历史结束不算**(不会一装上就一屏红点)。
- **当前正在看的会话**和**子代理会话**一律不计;门铃与"结束"两个来源按会话 id 并集去重。

### 存储

- 规则存 `$DSH_HOME/custom-favicon/unread.json`,**与图标库索引 `library.json` 分开**,避免一次设置写入弄坏图库。

### 图标的权威来源是插件状态,不是页面 HTML

- 合成红点时,**底图取插件自己状态里的当前图标**(`/icon-custom-192.png?v=<rev>` 或 `/icon-custom.svg?v=<rev>`),**不信任页面 `<link rel="icon">` 当时指向什么**。
- 理由(踩过的坑):页面 HTML 里的图标链接可能过期——反向代理/浏览器缓存旧首页、服务端改写时序、浏览器扩展都可能让它指向官方图标。而"当前用哪张图"这件事,插件状态才是权威。客户端发现链接不对时,顺手把它改成插件说的那张。
- 另加一个**看门狗**:图标被外部改掉后会自动补回来(监听 `<head>` 变化 + 页面重新可见/获得焦点 + 每 5 秒校正一次),因为标签页图标是这套功能里唯一会被第三方动到的地方。

### 唯一贴产品 DOM 的部分:工作区图标 + 会话行标题上的红点

- 需求:"只知道总数、不知道在哪"。会话行有官方的绿点/琥珀点,**工作区行什么也没有**。
- 但侧栏浏览区是一个 `single` 座位(`sidebar.workspaces`,只暴露一个 directoryFlow 洞),**没有"每一行"的插槽**;而且那片 DOM **没有任何 `data-*` 锚点**。
- 所以这一项只能**注入标记**,是本插件唯一贴着产品结构走的地方。为了让它的失败**不可能扩散**:
  1. **不在任何人的渲染树里** —— 不注册插槽、不是 React 组件,异常进不了别人的 render;
  2. **只读 + 只插自己的元素** —— 定位用官方 `[data-slot="sidebar.workspaces"]` 锚点 + **文本精确匹配**(不用打包后的类名);只 append 带 `data-icon-custom-wsdot` 的 8px 圆点,`pointer-events:none`,不改结构、不吃点击;
  3. **幂等** —— 每次重画先清掉自己所有标记,并还原被我们改过的 `position`;
  4. **熔断** —— 连续 3 次定位失败即本次会话内自动停用,只留一条 warn;
  5. **保险丝** —— 设置里的 `workspaceDot` 开关(宿主持久化),关掉即彻底不启动。
- **两个落点**:工作区行用"文件夹图标右上角的绝对定位圆点"(锚点必须含图标、且图标在文字左侧);会话行没有图标可锚,所以用"紧跟标题文字的行内圆点"(要求那一层是标题的**紧凑持有者**,包着时间戳的 wrapper 会被拒绝,否则点会被推到时间戳后面)。
- **对齐,而不是"擦掉重画"**(修过的坑):最初每轮绘制都是"先清空自己的标记、再全部重画"。结果是**任何一次瞬时定位失败**(列表正在重渲染、某个名字一瞬间匹配到两次)都会把上一轮已经画好的点清掉、这一轮又画不上 → 点会闪没;更糟的是官方 UI 重渲染时顺手删掉我们的标记,也会被观察器当成"我们自己的动作"忽略掉,于是再也不补。
  现在改成**对账**:已经正确的标记原封不动,只补缺的、只删"不再需要或已脱离文档"的;观察器只忽略**自己绘制后 250ms 内**的动静,之后任何人动 DOM 都会触发一次对账;每次**新建**标记后再安排一次 700ms 的"核对",防止官方 UI 恰好在我们静默窗口内提交渲染把新点带走。
- **失效时的表现**:最坏就是"少了某个点";不会白屏、不会卡顿、不会影响其他插件。

### 独立接口,不碰 `status()`

- 规则走自己的一对接口 `getUnreadRule` / `setUnreadRule`(**不加到 `status()` 上**)。
- 图标那 5 个接口(`getStatus` / `setIcon` / `setPwa` / `setLogo` / `resetIcon`)的返回形状**保持加这个功能之前一字不变**。
- 理由(踩过的坑):最初把 `unread` 塞进了**共享的 `statusSchema`**,等于把新功能的成败押在图标主干 RPC 上——这 5 个接口任何一个形状对不上,整条图标链路会一起坏,而图标本体(路由 + HTML 改写)不走 RPC,**坏了还看不出来**。新功能必须能单独失败。

## Consequences

- 动了宿主半边 → **需要重启 DSH** 才生效。规则本身的勾选不需要重启(走 `iconCustom/setUnreadRule` RPC)。
- 客户端与宿主各有一份默认值(浏览器半边不能 `import` 宿主模块),**以宿主为准**,客户端那份只用于首屏。
- 老会话可能没有投影行;缺行一律按**已读**处理(安全默认)。
- 规则层是一个纯函数文件(`lib/unread.js`),不碰 cordis/文件系统/其他插件,将来要拆成独立的包可以整体搬走。
